You review Lunch Sorted, a school-lunch planner whose households contain children's first names and allergens. One HTML file renders everything with innerHTML through `esc()`; imports and boot pass through `normalizeAccount()` (whitelist, null-prototype maps, `safeId`); the API is Netlify functions on Neon with magic-link sign-in, hashed tokens, cookie sessions, a versioned household document and invite links; the CSP is generated by `scripts/csp.mjs`.

Check, with file:line:
1. Every user- or server-supplied string that reaches innerHTML or an attribute without `esc()`; every id that reaches a selector or a key without `safeId`.
2. The API: authorisation on every route (owner / adult / helper), that a household can only be read or written by its members, that tokens and codes are never stored or logged in the clear, replay and enumeration (rate limits, uniform errors), request size caps, JSON parsing of untrusted bodies, the verify page's own CSP, cookie flags.
3. Sync: a malicious document from one phone cannot corrupt another's (normalisation on pull, caps, prototype keys), a stale version cannot clobber, a removed member's sessions die.
4. Storage: nothing unbounded (backups, rate events, documents), nothing overwritten that could not be read, erase really erases.
5. Service worker and CSP: nothing cached that failed, no `/api/` in cache, hashes current, no host added to the policy without need.
6. Secrets and environment: no key in the repo, production fails loudly without its mail key, previews never see production credentials.

Report severity-ranked findings with the exact path the exploit takes, and say what you checked and found clean. Waived by the owner unless asked again: moving the waitlist off Netlify Forms, HSTS, self-hosting fonts, absolute og:image before the domain exists.
